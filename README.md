# 공생관 분리형 구조

- `index.html`: 화면 구조(HTML)
- `css/style.css`: 디자인과 반응형 스타일
- `js/app.js`: 로그인, 투표, 일정, 지도, 날씨, 관리자, PWA·알림 등 동작
- `manifest.json`: 홈 화면 추가(PWA 설치) 설정
- `sw.js`: 서비스 워커 (PWA 설치 요건, 알림 클릭 처리)
- `assets/login-background.jpg`: 로그인 배경
- `assets/club-emblem.png`: 구단 엠블럼
- `assets/icon-192.png`, `assets/icon-512.png`, `assets/icon-maskable-512.png`: 홈 화면 아이콘
- `supabase-schema.sql`: Supabase 테이블/보안정책을 만드는 SQL (최초 1회 실행)

기능과 화면 내용은 원본을 유지하고, 한 HTML 안에 있던 CSS·JavaScript·Base64 이미지만 파일별로 분리했습니다.

GitHub에는 이 폴더 안의 파일과 폴더를 구조 그대로 업로드해야 합니다.

## 코드만 업데이트할 때(패치 배포) — 데이터는 그대로 안전합니다

데이터는 이제 이 파일들 안이 아니라 **Supabase에 따로 저장**되어 있습니다. 그래서 `index.html`, `css/style.css`,
`js/app.js` 같은 파일 내용을 고쳐서 GitHub에 다시 올려도, **Supabase 쪽 데이터(회원·투표·경기 기록)는 전혀
영향받지 않습니다.** 코드(화면·기능)와 데이터(회원·투표 등)가 서로 분리되어 있기 때문이에요.

패치할 때는 이렇게 하시면 됩니다.

1. 바뀐 파일만(주로 `js/app.js`, 필요하면 `index.html`, `css/style.css`) GitHub 저장소에서 열어 내용을 그대로
   교체하고 커밋합니다. `SUPABASE_URL`, `SUPABASE_KEY` 값은 그대로 두면 같은 데이터베이스에 계속 연결됩니다.
2. 배포된 주소에서 새로고침(캐시 때문에 안 바뀐 것처럼 보이면 Ctrl+Shift+R로 강력 새로고침)해서 확인합니다.
3. 테이블 구조 자체를 바꾸는 게 아니라면 `supabase-schema.sql`은 다시 실행할 필요 없습니다.

## 이번 패치에 추가된 기능

- **관리자 계정은 투표 인원 통계에서 제외**됩니다. "미투표 인원", 팀 순위, 참석 현황(N/전체 인원) 등 모든
  집계에서 관리자(`관리자` 계정)는 선수가 아닌 운영 계정으로 취급되어 빠집니다.
- **관리자 도구에서 확정 경기에 용병(게스트) 등록** 가능. "경기장·시간·링크·용병 등록" 항목에서 이름을 하나씩
  입력해 "추가" 버튼을 누르면 목록에 추가되고, 각 이름 옆 "✕"로 개별 삭제도 할 수 있습니다. (저장 버튼을 눌러야
  최종 반영됩니다.) 홈 화면의 "다음 경기" 카드에 참석 인원·아바타·명단에 "(용병)" 표시와 함께 같이 나타나고,
  **팀 순위(참석/미투표/불참 랭킹)에는 포함되지 않습니다** — 용병은 정식 팀원 명단과 완전히 분리되어 저장되기
  때문에, 애초에 순위 계산 대상에 들어가지 않는 구조입니다. 경기가 끝난 뒤 "실제 참석 체크"를 열면 이 용병
  명단이 자동으로 기본값으로 채워져 있어 다시 입력할 필요가 없습니다.
- **관리자 도구에서 "미투표 통계 제외 주간" 지정** 가능. 시험운영 기간처럼 팀 순위에 영향이 없어야 하는
  주간을 날짜 하나로 지정하면, 그 주(일~토) 전체가 **참석·미투표·불참 순위 전부**에서 완전히 제외됩니다.

## GitHub 업로드 전 체크리스트

- 파일/폴더 이름은 반드시 영문 그대로 유지하세요 (`index.html`, `css`, `js`, `assets` — 한글로 자동
  번역되면 배포 후 404나 스타일 깨짐이 발생합니다. 예전에 한 번 겪으셨던 문제예요.)
- 이 폴더 안의 파일은 전부 그대로 올리셔도 됩니다. 여기 포함된 키(카카오맵 JS 키, 기상청 API 키,
  Supabase publishable 키)는 전부 "브라우저에 노출되는 걸 전제로 만들어진 공개용 키"라서, 공개
  저장소에 올라가도 그 자체로는 문제가 없습니다 (도메인 제한 등으로 별도 보호돼요).
- 혹시 `migrate-from-jsonbin.html` 같은, 예전 JSONBin 마스터 키가 들어있는 파일을 따로 갖고 계시다면
  그건 올리지 마세요. 지금 이 폴더에는 포함돼 있지 않습니다.

## Supabase 연동 (신규)

데이터 저장소를 JSONBin.io에서 Supabase로 옮겼습니다. **기존 앱의 데이터 구조(appData 하나의 JSON 덩어리)는
그대로 유지**했고, 저장소만 바꿨기 때문에 화면·기능은 이전과 동일합니다.

### 처음 설정하는 순서

1. Supabase 대시보드 → **SQL Editor** → `supabase-schema.sql` 파일 내용을 그대로 붙여넣고 실행합니다.
   (`app_state`라는 테이블 하나와, id=1인 행 하나가 만들어집니다.)
2. `index.html`을 열어서 정상적으로 로그인 화면이 뜨는지 확인합니다.

### 기존 JSONBin 데이터는 옮기지 않고 새로 시작하는 경우

이번엔 기존 데이터를 이전하지 않기로 했으므로, Supabase의 `app_state` 테이블은 **완전히 빈 상태**로
시작합니다. 즉:

- 예전에 등록했던 회원(팀원)들이 전부 사라진 상태로 시작해요. 각자 다시 회원가입(로그인 화면에서 이름·생일·
  참석코드 입력)을 해야 하고, 관리자가 다시 승인해줘야 해요.
- 투표·경기 기록도 전부 처음부터 다시 쌓이기 시작해요.
- **관리자 계정(이름: 관리자 / 생일: 260402)은 코드에 그대로 남아있어서, 데이터가 비어 있어도 그대로
  로그인할 수 있어요.** 팀원들에게 다시 가입해달라고 안내해주시고, 관리자 도구에서 승인해주시면 됩니다.

### 지금 수준의 보안 상태 (꼭 읽어주세요)

지금 연결한 키(`sb_publishable_...`)는 브라우저에 그대로 노출되는 "공개 키"이고, 지금은 **로그인 여부와
상관없이 누구나 이 키로 데이터를 읽고 쓸 수 있는 상태**입니다. 이는 지금까지 쓰던 JSONBin.io 마스터 키
노출 방식과 보안 수준이 동일해서, 이번 변경으로 더 안전해지거나 더 위험해지지는 않았습니다.

다만 팀 인원이 늘어나거나 외부에 공개하게 되면, 다음 단계로 넘어가는 것을 권장합니다.

- **Supabase Auth 도입**: 지금의 "이름 + 생일 + 참석코드" 로그인을 Supabase의 정식 이메일/전화번호 로그인으로 교체
- **테이블 세분화**: 지금은 모든 데이터가 JSON 한 덩어리(`app_state.data`)에 들어있는데, 나중에 `members`,
  `votes`, `matches` 같은 진짜 테이블로 나누면 RLS(행 단위 보안)로 "본인 데이터만 수정 가능" 같은 세밀한
  권한 제어가 가능해집니다.

지금 당장은 팀 내부용 도구로 쓰기에 충분한 수준이고, 위 항목들은 필요하다고 느끼실 때 요청해주시면 이어서
진행하겠습니다.

## 홈 화면 추가(PWA)

`manifest.json`과 아이콘, `sw.js`를 추가해서 모바일 브라우저에서 "홈 화면에 추가"를 하면 앱 아이콘으로
설치되고, 실행 시 주소창 없이 앱처럼 열립니다. 아이콘은 구단 엠블럼을 어두운 배경(`#11161b`)에 맞춰
자동 생성했습니다.

## 경기 확정 · 투표 마감 알림

홈 화면 상단에 "알림 허용" 배너가 뜨고, 허용하면 브라우저 알림으로 아래 두 가지를 받아볼 수 있습니다.

- 새 경기가 확정되었을 때
- 목~토요일인데 아직 이번 주 투표(참석 선택 또는 불참 선언)를 하지 않았을 때

**중요한 제약사항**: 서버가 없는 순수 프론트엔드 구조라서 완전한 실시간 푸시 알림(앱을 완전히 꺼둔 상태에서도
도착하는 알림)은 지원하지 않습니다. 이 앱을 열거나 새로고침하는 시점에 상태를 확인해서 알려주는 방식이라,
브라우저 탭/앱을 아예 켜지 않으면 그 순간에는 알림이 오지 않고, 다음에 열었을 때 알려드립니다. 완전한 푸시가
필요하시면 Web Push로 확장할 수 있습니다 (Supabase Edge Functions로 트리거하는 방식 등).

카카오맵과 기상청 API는 등록한 도메인에서만 정상 동작합니다. GitHub Pages 등으로 실제 서비스할 주소가
정해지면 아래 두 곳에 그 주소를 등록해 주세요.

   (data.go.kr의 단기예보 API는 도메인 제한이 없습니다)

## 로컬 확인 방법

브라우저로 `index.html`을 더블클릭해서 바로 열면 `file://` 경로라 일부 기능(지도, 서비스 워커 등)이
정상 동작하지 않을 수 있습니다. VS Code의 Live Server 확장 등으로 로컬 서버를 띄워서
`http://localhost:...` 주소로 열어보시는 것을 권장합니다.

## 이번 패치에 추가된 기능 (2차)

- **관리자 도구 상단에 "지금 새로고침" 버튼** 추가. 페이지를 새로고침하지 않고도 Supabase의 최신 데이터를
  바로 불러와 화면을 갱신합니다. 웹/모바일 브라우저, 홈 화면에 추가해서 실행한 경우 모두 동일하게 동작합니다.
- **홈 화면 추가(PWA) 아이콘 여백 축소**. 아이콘이 이전보다 훨씬 꽉 차게 보입니다.
- **부상 상태(기간 지정) 기능**. 팀 멤버 스트립 옆 "내 부상 설정" 버튼으로 본인이 직접 부상 시작일~종료일을
  등록할 수 있고, 관리자 도구의 회원 관리에서도 각 회원의 부상 기간을 설정/해제할 수 있습니다. 부상 기간
  동안에는 투표(가능일 선택·불참 선언)가 막히고, 그 기간에 해당하는 날짜·주는 참석·미투표·불참 순위 집계에서
  전부 제외됩니다.
- **지도 탭 기본 동작 변경**. 이제 지도 탭을 열면 홈 화면과 동일하게 "가장 가까운 확정 경기"의 경기장을
  자동으로 보여줍니다. 다른 경기장을 보고 싶으면 기존처럼 목록에서 고르거나 검색해서 조회할 수 있습니다.
- **아이폰 홈 화면 앱 실행 시 화면 확대되던 문제 수정**. 뷰포트 설정을 조정해서 캘린더를 조작해도 화면이
  갑자기 확대되지 않습니다.
- **홈 화면 "최근 경기 기록"을 5경기까지, 한 줄에 한 경기씩** 보이도록 정리했습니다 (예전엔 경기장 이름이
  길면 두 줄로 넘쳐서 4경기만 표시됐습니다).
- **"휴식" 상태를 완전히 제거**했습니다. 이제 회원 상태는 "부상" 하나만 있고, 관리자 회원 관리 화면에서
  정상/휴식을 고르던 드롭다운도 없앴습니다.
- **부상 기간을 설정했다가 해제하면 회원이 삭제되던 오류를 수정**했습니다. 삭제 버튼과 부상 설정/해제
  버튼이 서로 혼동되지 않도록 각 버튼의 동작을 명확히 구분해서 다시 연결했습니다.
- **팀 멤버 전체보기 팝업**을 추가했습니다. 팀원이 많아져서 가로 스크롤로 보기 불편했던 문제를 해결하기
  위해, "팀 멤버" 목록이나 "전체보기" 버튼을 누르면 팝업으로 전체 명단(이름·생일·온라인 상태·부상 여부)을
  한눈에 볼 수 있습니다.
- **"불참" 기준을 명확히 정리**했습니다. 이제 불참 순위에는 "이번 주 전체 불참"을 명시적으로 선언한 경우만
  들어갑니다. 다른 날짜에는 투표했지만 일정이 안 맞아 확정된 날짜에 참석 못 하는 경우, 아예 투표를 안 한
  경우는 불참으로 잡히지 않습니다(후자는 미투표 순위에서만 집계됩니다).
- **관리자 도구에 "순위 횟수 수동 조정"** 항목을 추가했습니다. 각 회원의 참석·미투표·불참 횟수 옆에 자동
  집계값이 표시되고, 그 위에 더하거나 뺄 값을 직접 입력해 저장할 수 있습니다. 실제 투표 기록 자체는 바뀌지
  않고, 순위 계산에만 보정값이 더해집니다.
- **지도 전체화면 기능을 아이폰(홈 화면 앱 포함)에서도 동작하도록 재구현**했습니다. 아이폰 사파리는 임의의
  요소에 대한 전체화면 API를 지원하지 않아서, 화면 전체를 덮는 방식으로 직접 구현했습니다. 기본 지도
  크기도 더 키웠습니다.
- **지도에 등록된 모든 경기장 위치를 이름표와 함께 항상 표시**합니다. 기존처럼 특정 경기장을 조회하면
  그 경기장으로 지도가 이동하고, 동시에 목록에 있는 다른 경기장들도 참고용 핀으로 계속 보여서 전체적인
  위치 감각을 잡기 쉬워졌습니다.
- **선택한 경기장과 나머지 경기장을 시각적으로 구분**합니다. 지금 조회 중인 경기장은 진하고 크게(📍), 그
  외 경기장은 흐리게 표시돼서 어디를 보고 있는지 한눈에 알 수 있습니다.
- **경기장 즐겨찾기(자주 쓰는 곳) 기능**을 추가했습니다. 관리자가 경기장 선택 옆 별표(☆/★) 버튼으로
  즐겨찾기를 켜고 끌 수 있고, 즐겨찾기한 경기장은 목록 맨 위에 별도로 모여서 나오고, 지도에서도 금색으로
  강조돼서 구분됩니다.
- **관리자가 확정 경기 참석자를 직접 추가/제외**할 수 있습니다. 홈 화면 "다음 경기" 카드의 참석자 이름
  옆에 ✕ 버튼(관리자만 보임)으로 갑자기 못 오게 된 사람을 뺄 수 있고, "갑자기 오는 인원 추가" 선택창으로
  갑자기 오게 된 사람을 더할 수 있습니다. 이 변경은 팀 순위(참여횟수)에도 그대로 반영됩니다.
- **지도의 경기장 이름표가 서로 겹쳐 보이던 문제를 해결**했습니다. 이제 평소에는 핀만 보이고, 핀을
  터치(클릭)하면 그 경기장 이름·주소가 말풍선으로 뜨고 ✕를 누르면 닫힙니다. 즐겨찾기한 경기장은 이름
  없이 작은 별(⭐) 표시만 얹혀서, 터치하기 전엔 이름이 겹치거나 즉시 뜨지 않습니다.
- **지도 경기장 표시를 다시 다듬었습니다.** 경기장 이름은 이제 지도에 항상 보이되(웹/모바일 화면 크기에
  맞게 글자 크기가 자동 조정됩니다), 터치하면 주소와 "주소 복사" 버튼이 펼쳐지고, 다른 핀이나 지도 빈
  공간을 누르면 자동으로 닫힙니다. 아이콘으로 종류를 구분합니다 — 📍 일반 경기장 / ⭐ 즐겨찾기 /
  ⚽ 확정된 경기 경기장(가장 눈에 띄게 표시).
- **지도 핀의 이름이 안 보이거나(웹), 상세정보가 세로로 깨져 보이던(모바일) 문제를 수정**했습니다. 원인은
  카카오맵의 CustomOverlay가 내용이 바뀌어도 크기를 자동으로 다시 계산하지 않는 것이었는데, 내용을 바꿀
  때마다 강제로 다시 계산하도록 고쳤습니다. 핀 배경도 흰색+진한 글자로 바꿔서 지도 위에서 대비가 훨씬
  잘 보이도록 했습니다.
- **관리자가 확정 경기 참석자를 직접 추가/제외**할 수 있습니다. 홈 화면 "다음 경기" 카드의 참석자 이름
  옆에 ✕ 버튼(관리자만 보임)으로 갑자기 못 오게 된 사람을 뺄 수 있고, "갑자기 오는 인원 추가" 선택창으로
  갑자기 오게 된 사람을 더할 수 있습니다. 이 변경은 팀 순위(참여횟수)에도 그대로 반영됩니다.
- **관리자 도구 "순위 횟수 수동 조정"에 집계 기간 안내를 추가**했습니다. 오늘 날짜 기준으로 참석/불참은
  어떤 경기 날짜까지, 미투표는 어떤 주까지 자동 집계에 포함됐는지 명확히 보여줘서, 수동 조정값을 얼마나
  넣어야 할지 판단하기 쉬워졌습니다.

## 경기 탭 (신규, 플랩풋볼 연동)

`plab-sync-test` 브랜치에서 만든 GitHub Actions 자동 수집 파이프라인이 Supabase의 `public.plab_matches`
테이블에 저장해둔 데이터를, 새로 추가된 "경기" 탭에서 **읽기 전용으로 조회**해서 보여줍니다.

- 상단에서 오늘부터 14일치 날짜를 가로 스크롤로 고를 수 있고, 기본값은 "오늘"입니다.
- 선택한 날짜의 경기 개수와 마지막 동기화 시간(`updated_at` 기준)을 보여줍니다.
- 시간대(오전/오후/저녁) 필터와 "즐겨찾기 구장만 보기" 필터를 중복 적용할 수 있습니다. 즐겨찾기는
  지도 탭에서 관리자가 지정한 것과 **동일한 데이터**를 사용합니다 (localStorage가 아니라 Supabase에
  저장된 `appData.favoriteVenues`를 그대로 참조합니다 — 기기가 달라도 동일하게 보입니다).
- "최신 경기 불러오기" 버튼은 GitHub Actions를 실행하지 않고, Supabase에 이미 저장되어 있는 데이터를
  다시 조회만 합니다.
- 카드에는 시간·경기장명·모집 상태(🟢모집중/🟠마감임박/🔴마감)·신청하기 버튼만 보여주고, 경기 번호·가격·
  URL 텍스트는 화면에 표시하지 않습니다.

**⚠️ 확인이 필요한 부분**: 플랩 API의 실제 응답을 직접 본 적이 없어서, "모집 상태" 판정은
`apply_status`가 `'full'`이면 마감, 그 외에는 `참여인원/정원` 비율(80% 이상이면 마감임박)로 계산하도록
만들었습니다. 실제 데이터로 확인해보시고 기준이 다르면 `js/app.js`의 `getMatchStatus()` 함수만 고치면
됩니다. 즐겨찾기 경기장 매칭도 이름이 정확히 일치하지 않을 경우를 대비해 부분 포함 비교까지 함께 하도록
해뒀는데, 실제로 안 맞는 경우가 있으면 알려주세요.

GitHub Actions, `scripts/fetch-plab.js`, Supabase 테이블 구조, 기존 홈/날씨/캘린더/지도/기록 기능은
이번 작업에서 전혀 건드리지 않았습니다.

**Supabase 쪽에서 한 가지 확인해주세요**: `plab_matches` 테이블도 `app_state`처럼 RLS(행 단위 보안)가
켜져 있다면, 공개(anon) 키로 조회할 수 있도록 **읽기(select) 정책**이 있어야 합니다. 없으면 경기 탭에서
"경기 정보를 불러오지 못했습니다" 오류가 뜰 수 있어요. (쓰기 권한은 필요 없고, 조회만 되면 됩니다.)

## 이번 패치 (경기 탭 개선 + UI 정리)

- **하단 탭 순서 변경**: 홈 / 캘린더 / 경기 / 지도 / 날씨 / 기록 / (관리자만) 관리자
- **경기 탭에 페이지네이션 추가**: 한 페이지에 10경기씩, 하단에 "‹ 이전 / 1·2·3 / 다음 ›" 버튼으로 이동합니다.
- **경기 탭 필터를 한 줄로 정리**: 오전/오후/저녁/즐겨찾기 버튼이 가로 한 줄에 나란히 놓이고, 화면이 좁으면
  가로 스크롤됩니다. 즐겨찾기 버튼이 줄맞춤 안 되던 문제를 고쳤습니다.
- **경기 수 표시 오류 수정**: 필터를 걸지 않은 전체 개수 대신, 실제로 화면에 보이는(필터링된) 경기 수를
  표시하도록 고쳤습니다.
- **"내 부상 설정" 버튼을 헤더로 이동**하고, 로그아웃 버튼을 그 오른쪽(맨 끝)으로 옮겼습니다. (이전에는
  팀 멤버 목록 옆에 있었습니다.)
- **모집 상태 진단 로그 추가**: 실제 `apply_status` 값이 무엇인지 브라우저 콘솔(F12)에서 바로 확인할 수
  있도록 로그를 남기게 했습니다. 모집중/마감임박/마감 판정이 실제와 다르면, 콘솔에 찍힌 값을 알려주시면
  `getMatchStatus()` 함수의 기준을 정확히 맞춰드릴게요.

## 경기 카드 레이아웃 변경 (스크린샷 기준)

시간 / 경기장 이름 / 모집 상태를 한 줄에, 그 아래 경기 종류 태그(있으면), 맨 아래 오른쪽에 신청하기
버튼이 오는 구조로 바꿨습니다.

**⚠️ "경기 종류(6vs6 등)" 태그는 아직 표시되지 않을 수 있습니다.** 이 정보는 지금 `plab_matches`
테이블에 저장되어 있지 않은 항목이라, `team_size`/`match_type`/`game_type`/`category`/`level_name`
같은 이름으로 혹시 존재하면 자동으로 표시되게 만들어뒀지만, 실제로 없으면 태그 자체가 안 보입니다
(빈 칸을 억지로 보여주지 않도록 했습니다). 이 데이터를 실제로 보여드리려면 `fetch-plab.js`가 플랩
API 응답에서 이 필드를 추가로 수집해서 Supabase `plab_matches` 테이블에 새 컬럼으로 저장해야 하는데,
이건 이전에 "GitHub Actions/fetch-plab.js/Supabase 구조를 건드리지 말라"고 하셨던 부분과 겹쳐서
확인 없이 진행하지 않았습니다. 이 데이터도 보여드리길 원하시면 말씀해주세요 — 그러면 `fetch-plab.js`에
필드를 추가로 저장하는 부분과 Supabase 테이블에 컬럼 추가하는 SQL을 같이 준비해드릴게요.

## 경기 카드 레이아웃 재조정 (모바일 예시 기준)

- 상단: 시간 + 경기장 이름 (더 이상 말줄임표로 자르지 않고, 길면 줄바꿈되어 전체가 다 보입니다)
- 하단: 모집 상태 / 인원수(N:N) / 신청하기 버튼

**인원수(6:6, 5:5 등)는 새 데이터가 필요 없었습니다** — 이미 저장되어 있는 `max_player_cnt`(정원)를
절반으로 나눠서 "한 팀당 인원수:한 팀당 인원수" 형태로 계산해서 보여줍니다. (예: 정원 12명 → 6:6)

## 중요 버그 수정: confirm_cnt → confirm_count

실제 Supabase `plab_matches` 테이블의 컬럼명이 `confirm_count`(정식 표기)인데, `js/app.js`의 모집 상태
판정 코드가 `confirm_cnt`(줄임말)로 잘못 읽고 있었습니다. 이 오타 때문에 인원수 기반 "마감임박" 판정이
항상 실패했을 가능성이 높습니다. 이번에 정확한 컬럼명으로 고쳤습니다.

**`scripts/fetch-plab.js`도 같은 이유로 별도 파일로 다시 수정해서 드렸습니다** (안내 메시지 참고). 저장
시 쓰던 컬럼명도 `confirm_cnt` → `confirm_count`로 고쳤고, 실제 스키마에 있는 `level`, `gender`,
`type`, `is_parking_available` 컬럼도 함께 저장하도록 추가했습니다.

## 경기 종류(인원수) 표시 방식 변경

`max_player_cnt`를 절반으로 나눠서 "9:9", "8:8"처럼 억지로 계산하던 방식을 없앴습니다. 이제
**Supabase `plab_matches`의 실제 `type` 컬럼 값을 그대로 사용**합니다 (계산하지 않습니다). `type`
값이 없는 경기는 이 표시 자체가 안 보입니다. 뱃지 디자인도 상태 표시와 어울리는 파란색 계열 pill
모양으로 다듬었고, `level`(급수)·`gender`(성별) 컬럼에 값이 있으면 그 위에 작은 보조 태그로 함께
보여줍니다.
